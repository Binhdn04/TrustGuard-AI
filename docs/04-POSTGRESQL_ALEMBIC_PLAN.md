# PostgreSQL and Alembic Plan — Contract v3

**Status:** frozen for Wave 0  
**Owner:** Hải — API/Platform  
**Source of truth:** PostgreSQL 16+ with `pgvector`; Redis is never authoritative.

This document fixes table ownership, keys, lifecycle constraints, and migration order before the
Wave 1 repository implementation. Names below are stable integration seams. A later migration may
add columns or indexes, but must not reinterpret an existing column in place.

## 1. Database rules

- Public IDs are UUIDs generated by the application. All timestamps are `timestamptz` in UTC.
- Mutable resources carry `created_at`, `updated_at`, and an integer `version` where optimistic
  concurrency is user-visible. Audit records and analysis events are append-only.
- Contract enums are stored as constrained `text`, not PostgreSQL enum types, so rolling deploys can
  add values without locking a type migration. Alembic owns each check constraint explicitly.
- Foreign keys use `ON DELETE RESTRICT` for audit/provenance and `ON DELETE CASCADE` only for data
  that has no independent audit value (for example, an unreviewed step belonging to an analysis).
- User input is minimized and encrypted at the application boundary. Search, metrics, logs, and
  outbox payloads must not copy raw messages, URL credentials/query secrets, prompts, or OTPs.
- Every owner read is scoped by `owner_id`; admin access is checked in the service layer and recorded
  where it changes state. Connection roles grant the worker only the tables it needs.

## 2. Frozen relational schema

| Table | Required columns and constraints | Primary indexes |
|---|---|---|
| `analyses` | `id` PK, `owner_id`, encrypted/minimized input, input hash, consent, status, typed result columns, `scoring_version`, timestamps, `version`; completed rows satisfy the v3 completed-result invariant | `(owner_id, created_at desc)`, `(status, created_at)`, `(case_status, created_at)` |
| `analysis_events` | `event_id` PK, `analysis_id` FK, `sequence >= 1`, `event_type`, schema-valid `payload jsonb`, `occurred_at`; unique `(analysis_id, sequence)` | `(analysis_id, sequence)`, `(occurred_at)` |
| `investigation_steps` | `(analysis_id, step_id)` PK, tool, canonical target or redacted target ref, reason code, dependency IDs, status, attempt count, timestamps | `(analysis_id, status)` |
| `evidence` | `id` PK, `analysis_id` FK, type, normalized source/version, title, safe URL or artifact ref, finding, observed/created times, content hash; no raw provider body | `(analysis_id, created_at)`, `(content_hash)` |
| `analysis_reports` | `id` PK, `analysis_id` FK, `reporter_id`, reason, optional comment, timestamp; append-only | `(analysis_id, created_at)`, `(created_at desc)` |
| `analysis_jobs` | `id` PK, `analysis_id` FK, kind, status, attempt/max attempts, available/claimed/lease times, worker ID, idempotency key, redacted failure code; unique idempotency key | claim partial index on `(available_at, created_at)` for queued/retry rows; `(analysis_id, kind)` |
| `outbox` | `id` PK, aggregate type/id, event type, minimized payload, created/published times, attempt count, lease fields, idempotency key unique | unpublished partial index `(created_at)` |
| `tool_usage` | `id` PK, `analysis_id` FK, step ID, provider/model/version, operation, units/tokens, estimated cost, latency, cache status, outcome, HTTP class, observed time; no target/prompt | `(analysis_id, observed_at)`, `(provider, observed_at)`, `(outcome, observed_at)` |
| `appeals` | `id` PK, `analysis_id` FK, `owner_id`, reason/comment, status, timestamps, `version`; one active appeal per `(analysis_id, owner_id)` via partial unique index | `(owner_id, created_at desc)`, admin queue `(status, created_at)` |
| `review_decisions` | `id` PK, nullable analysis/appeal/action IDs, reviewer, decision/outcome, action, immutable evidence snapshot, note, timestamp, predecessor decision ID | resource FKs, `(decided_at desc)` |
| `admin_actions` | `id` PK, nullable analysis/campaign IDs, reviewed action, canonical target, status, evidence snapshot, proposed/reviewed/executed times, `version`; non-`none` actions cannot execute without an approved decision FK | `(status, proposed_at)`, target/action lookup |
| `blacklist_entries` | `id` PK, canonical registrable domain unique, active flag, enabling decision FK, nullable disabling decision FK, timestamps, `version`; provenance decisions are immutable | active partial index on canonical domain, `(updated_at desc)` |
| `fact_check_sources` | `id` PK, publisher, allowlisted origin, active flag, policy version, timestamps | unique normalized origin |
| `fact_check_records` | `id` PK, source FK, source URL, publisher, normalized claim, stance, language, published/updated/ingested times, content hash, record version, ingestion provenance | unique `(source_id, content_hash, record_version)`, language/time |
| `fact_check_embeddings` | `(record_id, embedding_version)` PK, model, dimensions, `vector(1536)`, embedded time | HNSW cosine index plus `(embedding_version)` filter |
| `campaign_clusters` | `id` PK, hypothesis, time window, thresholds/config version, reviewer status, timestamps, `version`; a cluster is only a hypothesis | `(reviewer_status, created_at)`, window |
| `campaign_members` | `(campaign_id, analysis_id)` PK, match kind, similarity nullable, evidence refs; sender identity is forbidden | `(analysis_id)` |
| `campaign_signals` | `(campaign_id, signal)` PK, aggregate count; no raw private message | `(campaign_id)` |
| `artifacts` | `id` PK, analysis FK, storage key, media type, size/hash, created/expiry/deleted times; access tokens are never stored | expiry partial index for retention worker |
| `schema_imports` | importer name/source fingerprint PK, started/completed times, row counts and redacted error summary | `(completed_at)` |

Embedding dimension is deliberately fixed in the first corpus table. A model with a different
dimension gets a new embedding table/column and dual-read migration; it must not silently mix vectors
in the existing cosine index.

## 3. Transaction boundaries

1. Analysis creation inserts `analyses`, sequence-1 `analysis_events`, `analysis_jobs`, and `outbox`
   in one transaction. Publishing to Redis happens only after commit.
2. A worker claim uses `FOR UPDATE SKIP LOCKED`, records a lease, and is idempotent by job key.
   Completing a job writes result/evidence/events/usage plus outbox records atomically.
3. Sequence allocation locks the parent analysis row; `(analysis_id, sequence)` is the final guard
   against duplicate events. Delivery remains at-least-once and clients deduplicate by `event_id`.
4. Appeal and reviewed-action decisions append `review_decisions` and update the resource version in
   one transaction. Blacklist enable/disable is part of that same transaction. Old decisions are
   never updated or deleted.
5. Campaign detection can create hypotheses and members, but only an approved `admin_actions` row can
   create a block or broad warning.

## 4. Alembic revision sequence

| Revision | Contents | Deployment gate |
|---|---|---|
| `0001_extensions` | Enable `pgcrypto` and `vector`; create migration metadata/check helpers | Extension availability verified before traffic |
| `0002_analysis_core` | Analyses, events, steps, evidence, reports and owner/read indexes | v3 core repository contract tests |
| `0003_durable_jobs` | Jobs, outbox, tool usage, leases and idempotency constraints | restart/duplicate/outbox recovery tests |
| `0004_review_lifecycle` | Appeals, immutable decisions, admin actions and blacklist lifecycle | appeal-overturn and atomic action tests |
| `0005_fact_check_corpus` | Sources, records, embeddings and vector indexes | citation/version/rollback tests |
| `0006_campaign_artifacts` | Campaign tables and retained artifact metadata | privacy, retention and approval-boundary tests |

Migrations use expand/migrate/contract: add nullable or defaulted structures first, deploy dual-write
or backfill, switch reads, then remove obsolete structures in a later release. Indexes that can block
large tables use a separate non-transactional `CREATE INDEX CONCURRENTLY` revision. Production
downgrades are not relied upon for data recovery; rollback means application rollback plus a
forward-fix migration and restore drill where needed.

## 5. SQLite development import

Wave 1 provides a separately invoked, restart-safe importer after `0003_durable_jobs`:

1. Open SQLite read-only and fingerprint the file in `schema_imports`.
2. Validate every row through the frozen Pydantic v2 model, normalize UTC/UUID/domain values, and
   preserve IDs and decision provenance.
3. Import bounded batches with `INSERT ... ON CONFLICT DO NOTHING`; record counts per table.
4. Re-read PostgreSQL rows through v2 and v3 response adapters and compare semantic fields.
5. Mark the fingerprint complete only after all validation passes. A rerun is idempotent.

The importer does not synthesize appeal, campaign, usage, or provider records absent from SQLite.
Malformed rows are quarantined with IDs and error codes, never raw sensitive payloads.
